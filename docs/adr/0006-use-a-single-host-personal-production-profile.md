# Use a single-host personal production profile

The user selected one application container from the existing image under a Komodo stack configured directly on the server rather than stored in a repository, with MariaDB on the same host, startup migrations, filesystem media that may later migrate to S3, no automated recovery requirement, and no required observability integration. The repository derives the remaining runtime contract from those choices: use Laravel's private local disk with a persistent `/var/www/storage/app` mount, use the synchronous queue while no queued jobs or worker are required, retain the image's existing cron process while no application-specific schedules exist, and recommend Laravel's shallow `/up` route as the Komodo or proxy health signal so a MariaDB outage does not create a restart loop. These derived settings are required or recommended configuration, not evidence that the live Komodo stack already applies them. Host loss may lose database and media data, and application logs are limited to configured stderr unless the existing OpenTelemetry stack is connected later. Revisit this decision before adding replicas, asynchronous work, operational recovery objectives, or storage that must survive loss of the host.
